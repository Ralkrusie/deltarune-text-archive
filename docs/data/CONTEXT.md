# 上下文契约

上下文是同文件文本引用、局部选项和条件分支的静态结构。当前为测试版，不是完整执行图，也不提供运行时角色或样式归因。

## 输入与产物

输入为与语言表版本对应的 GML 根目录，含 `ch1..ch5/`，每章直接放 `.gml` 文件；使用者自行通过 UMT 反编译。构建与验证命令见[构建说明](../build/README.md)。

`local/context-all/` 包含：

| 文件 | 内容 |
|---|---|
| `contexts.json` | schema 2 目录与文本 manifest 摘要 |
| `index-chN.json` | 章节文件清单和 key 到文件的索引 |
| `files/<id>.json` | 每个源码文件的结构及消息引用，按需加载 |
| `evidence.json` | 源码及输出摘要、大小和统计 |

网站装配核验绑定和每个分包的摘要、大小、身份与索引覆盖；过期或损坏的包会报错。修改语言表或 GML 后应重新生成并验证，不手改结果。

## 用法与关系

- 同 key 的不同引用保留独立 `occurrence_id`、文件、行号和文本绑定。
- 身份中的 `data/exported/code/chN/...` 是逻辑命名空间，不是磁盘路径；移动输入目录不改变身份，变更反编译格式可能改变身份。
- 消息节点类型为 `message`；容器为 `sequence/block/blocks`；分支为 `choice/condition`，端点为 `end/join`。
- 无法确定的动态调用、消费关系、分支连接保留未知或独立块，不猜顺序、汇合或全局路线。
- 无源码引用的语言表项仍保留。没有引用不证明不可达；没有运行记录也不证明分支不存在。

## 提前退出的前置检查

直接的 `if (条件) exit;` 会给同一语句列表的后文附上未触发退出的条件。函数内部还支持直接的 `return;` 或返回常量；不把嵌套的、有其他语句或有 else 的退出分支提升为前置检查。检查不会从分支、循环、with、switch case 内传播到外部；函数声明和延迟执行的匿名函数不继承外面的检查。

节点的 `entry_guards` 保存 `condition`、`source.file/line`、`meaning: "passed_at_source"` 与 `visible`。它表示执行到那一行时通过了检查，即使之后变量改写也保留这条历史事实，不能当作台词显示时变量仍取相同值的保证。网页显示短标签“前置：条件”，来源行和含义放在悬停说明中。纯 `con/customcon` 与整数的比较仍保存，但不额外显示。

当前匹配 271 处检查，按章为 2／6／74／61／128，其中 108 处可见、163 处为不显示的流程检查。证据规则为 `passed_exit_guard`。例如 CH4 `obj_ch4_PDC04` Step L820 的“不准甩掉我”现在同时保留 L810 的 `!(global.plot < 25)` 和原有 `leave_con == 1`；CH3 `obj_room_ranking_b` Step L30 的“伸腿”保留 `!(global.flag[1226] == 1)`，L9 位于检查之前的文本不受影响。

## 局部选择的自动连接

同文件中，选项写入、选择控制串和唯一的状态响应块可对应时，将选项与 `global.choice` 消费分支连接。支持以下共性写法：

- `global.choicemsg[i] = ...` 逐槽赋值，以及 `global.choicemsg = [...]` 整数组赋值。
- 从实际消息调用中的 `\C2`、`\C3`、`\C4` 确定可见选项数；数组或逐槽赋值末尾的空占位不当成选项。
- 独立 `if (global.choice == i)`、`else if` 链，以及能唯一对应剩余一个选项的末尾 `else`。
- 选项内部的 flag 等条件原样保留，不推测变量的剧情含义。没有可定位响应文本的选项在网页上留空，不加说明框或悬空箭头；本地证据的 `empty_options` 保留这些选项编号。留空不表示整个对话结束，后续未关联状态仍独立显示。

除原有顶层 `con` 规则，也从裸变量的整数判断、赋值和选择消费中识别状态变量，例如 `myinteract`、`talk_con`。新规则要求菜单块与响应块是同一语句列表中的相邻块，响应状态只有一个明确写入来源；菜单直接清空 `global.choice`，选项与控制串也须可直接定位。每个 `with(标识符)` 独立分析，外层条件保持；不同 `with`（包括表达式相同的两段）、条件两侧、循环、函数和动态对象表达式之间不连接。

若事件中有可能遮蔽状态名的局部声明，或所属作用域存在动态／限定对象写入、按字符串指定状态名的延迟调用，则暂不连接。证据规则 `scoped_choice_slots_to_state` 保存变量名、起止状态、菜单／响应行号及包含 `with`、条件分支的作用域路径。它证明局部菜单与响应结构，不证明任意外部事件不会中断对话。

已连接选项中的直接 `scr_flag_get(N) == 0` 判断，若真分支第一句无条件执行 `scr_flag_set(N, 1)`、两边都有文本，且本文件没有该 flag 的其他 setter、动态 setter 或直接数组写入，可标为 `condition.revisit`。另外须核验 get/set 函数确实访问 `global.flag`，两边只含已识别文本调用和 `scr_speaker`；嵌套控制流、未知调用及其他写法不套用此规则。

这类条件上下展示“首次选择／再次选择”，保留原始条件；两组之间不画连续播放箭头。`revisit` 保存 flag、0→1 和写入行号，`choice_flag_revisit` 证据注明局部范围。这表示 flag 从 0 开始且期间未重置时的重复选择关系，不保证初始存档状态，也不证明其他文件不会修改该 flag。当前匹配第五章 4 个文件的 7 处，其余条件仍左右排列。

选择响应后若有同一语句块内的公共文本，可用 `choice/condition.join_next: true` 表示汇合到紧随其后的消息节点。公共文本保留为分支外的唯一节点，沿用原 `occurrence_id`；不按 key 或内容去重。已对应菜单的选择保持选项标签，尚未对应菜单的分支保持原始 `global.choice` 条件，不据此推断选项名称。

汇合规则只接受直接消息调用；分支及公共文本前的路径不能有提前退出、循环、未知调用、choice 改写或新的选择提示。已识别的消息、头像和队列动作调用可保留；跨状态、回调和动态菜单不由此规则连接。网页在宽屏上用汇合线接向公共文本，窄屏保持纵向排列。当前真实数据匹配 3 处 `choice_common_tail`（第三、四、五章各 1 处）；三处旧版均已保留公共文本，这次增加明确汇合关系，没有新增菜单到响应的对应。

动态标签、覆盖写入、重复选项编号、多个来源写入同一响应状态、响应期间改写 choice 或提前退出，以及需复制到多个选项的共享默认分支，目前不强行连接。`switch(global.choice)`、经局部变量转存的选择、间隔多个状态的后文仍可能只显示原始条件或独立块。规则不按具体场景、角色名或 key 特判；协议规则会定位并核验相应公共脚本。

## 共享 scr_text 选择

`shared_case_choice` 连接 `scr_text` 内符合协议的菜单 case 与响应 case。逐章检查 writer 的 `\C2/3/4`、选择器的选项槽与方向编号、`global.choice` 写入，以及 Alarm 中 `global.msc += 1; scr_text(global.msc);`，再核验菜单和响应。相邻编号本身不足以证明关系。

当前只接受以下子集：

- 菜单直接逐槽写入本地化选项，只有一条可定位的选择提示，且菜单和下一编号 case 均以 break 结束。
- 提示可以位于 flag 判断的一侧；连接仅放在该侧，另一侧不会凭空出现菜单。第一章 getter 从绑定的英文表读取控制串，后几章从源码默认文本读取。
- 响应可为单个互斥 if/else 链，各选项均有唯一可归属的分支；内部嵌套条件保留。共享响应前缀有未知调用、提前退出及未归属的公共后文均不连接。
- 多个独立 `if (global.choice == 常量)` 仅在编号无重复、恰好覆盖固定选项、没有 else 或嵌套新菜单，且菜单与整个响应均通过副作用检查时连接。逐章读取本地化、消息写入、说话样式和头像控制串辅助函数的唯一源码定义，连同依赖核验；函数体或依赖不符就拒绝，证据保存文件摘要。限定常量消息／flag 写入及局部标量计算可保留；`with`、事件、未知调用、动态调用、答案改写和其他对象状态写入不放行。这层检查只证明本次回答构建期间答案不变，不展开辅助函数内的台词或其他文件的续段。
- 提示后的空白消息槽只有在直接、常量、按序写入且没有覆盖前文时才放行；逐章核验 writer 在提示处 `halt = 5`，选择确认时销毁旧 writer，再递增编号、调用共享脚本和重建消息。空白引用仍保留，标为引用而非后续对话页。正文、控制串、动态槽和未核验副作用不能当作填充跳过。
- 下一 case 可在判断旧答案前准备下一题的固定选项；必须先独立证明下一题的提示与响应，再嵌入旧答案对应的分支。选项赋值位置不等于选择出现位置。仅按连续编号向前连接，不处理循环或共用回答目标；新题依赖既有已核验的选择器创建／答案重置协议。
- 下一题可见选项放在其提示处，公共前缀中的未使用选项槽引用只保留一次；各题的空白填充保留自己的 occurrence。未知新题不会使父题绕过检查；父题未获证时，已独立获证的子题仍可单独展示。
- 全章扫描 `scr_text` 入口。直接字面量调用只有在同语句列表中紧接着同值 `global.msc` 赋值时可纳入；否则排除相应编号。动态参数、间接调用等使本章这条窄规则停止匹配。证据保存已绑定与排除的字面量入口。

当前匹配 174 处，按章为 21／39／39／37／38，包含跨章保留的旧文本及 `Choice text/Result A/B` 测试条目。它们是源码结构匹配次数，不是 174 个实际可触发场景，也不能用先前扫描的 794 对宽泛候选计算覆盖率。加上 57 处原有选择、8 处同文件队列选择和 8 处直接对话框选择，总数为 247，按章为 21／39／44／49／94。同一文件内不复制 occurrence，不把响应复制到多个菜单。

## 跨文件续段的候选评估（尚未接入）

只读调查命令：

```sh
python -m tools.context.audit_shared_returns --code "PATH_TO_GML" --out build/context-cross-script/census.json
```

当前五章 36,857 个 GML 文件中，调查能按字面量参数或紧邻的 `global.msc` 常量赋值定位 465 处共享菜单调用。这里统计调用位置，含跨章副本、旧内容和测试内容，不代表独立场景数或正常游玩覆盖率。动态参数及不能直接绑定的入口不纳入该分母。

- 31 处调用的下一共享 case 对原场景写入多个目标状态；15 处写入单一目标状态，该状态块里又判断 `global.choice`。这 46 处是优先候选，40 处在同一调用者文件的候选目标块中能直接找到文本。仍须证明状态写入、选项和目标块的对应，不能把同文件出现的 choice 判断直接当成该菜单的回答。其余目标可能在其他事件或需要继续经过动画状态。
- 另有 13 处把答案交给对象方法的调用；只有 CH4 DCC03 的简单 `answer_choice` 能被现有回调规则求值且已经接入。其他方法可能先存入 `answer`、改变玩法或依赖额外条件，暂不一并展开。
- “下一 case 仅有 `%%`，调用对象另有答案判断”的窄候选为 2 处：CH2 scene10 的“双峰／毁灭”和 CH3 swordroute_consolestarter 的“是否玩游戏”。后者主要引出动作状态，不能把它算成同等数量的新增台词。
- 另有 38 处仅观察到一般状态续段的候选，未计入上述分支收益。

已核对的代表：CH2 送礼菜单 1083／1084 明写 `obj_ch2_city07.con = 10/20/30/40`；CH3 1331／1332 回到 `obj_room_green_room.con = 125`，该块区分“打游戏／没干什么”后有公共后文；CH4 1300／1301 回到 PDC06B 的 con 4 后读取答案。反例包括 CH4 Alphys 菜单按 flag 增减选项，以及 CH3 谜题回调只把参数存入 `answer`。

建议先支持固定菜单、命名对象和常量目标状态；逐章核验共享选择协议、队列调用、等待结束、状态唯一性及途中没有新菜单／答案改写。缺任一证据时保留分块，不画确定连线。Queen 这类等待关闭的写法另核验局部状态链；不把“对话框消失”本身当作某菜单的完成证明。此处只有候选盘点和源码样本核对，尚无新增连接的准确率或最终覆盖量。

展示拟以调用者文件为主：保留同文件全部文本，在获证调用位置引用对应共享 case 的菜单／前文，接到本文件回应；只在跨文件边界标注来源，消息仍保留原 key、源码链接和 occurrence 身份。打开共享脚本时继续显示其全文，通过已有文件选择器进入各个“关联调用”；多个调用者分开看，不合成一条路线。公共后文及被多个选项指向的同一目标只保留一个落点；重复调用保留各自调用位置，不能按相同文本去重。

## 同文件队列选择

`queued_local_choice` 单独处理同一事件文件中的队列菜单，不放宽旧规则，也不展开跨文件续段。当前匹配第五章 8 处：温泉 `obj_ch5_DWC_Onsen` Step 的提示行 135／401／451／1266，`obj_dw_fcastle_right_endingscene` Step 的 211／242／671，以及 `obj_town_mid_temmie` Step L217 的大学选择。温泉和饮料券两文件分别为 4／3 个 choice 节点，237／96 处原始文本引用保持。其中饮料券所在文件的 1.2／1.26 两题只切换状态，当前分支没有文本，后续状态仍独立。

连接要求：

- 菜单直接设置 `global.msc = -99`、清空答案、写入固定选项并排入 `\C2/3/4`。实际创建函数须能从源码证明只创建对话框及可选设置常量 side／stay；支持命名函数和匿名函数，不依赖 `make_choice` 名字。选项本地化 getter 也须核验，不能只检查调用位置。
- 逐章核验队列写入、所属对象、对话框、选择器与共享脚本返回协议；`c_waitcustom` 对 `master_object.customcon` 写 1 并暂停队列，不能只按函数名假定用途。响应须为唯一的后续常量 `con` 状态，并检查 `customcon == 1 && global.choice != -1`。常量小数状态按数值比较，`1.10` 与 `1.1` 不算两个状态。
- 菜单可位于上一题的分支内，父条件仍保留。先独立证明新菜单，再把新答案接到自己的响应，避免混用两次 `global.choice`。响应必须覆盖固定选项，公共文字不复制。
- 菜单前已排入的命令、条件表达式、菜单剩余语句及响应整体都要通过有限副作用检查。消息、动作包装器及命令处理器从源码核验，未知回调拒绝；不能认为同步清空答案就能抵消稍后执行的回调。
- 同一答案被再次读取时，只接受没有文本、没有新菜单的已核验动作。限定对象或动态状态写入、局部变量遮蔽、竞争状态来源、提前终止队列、未知副作用均不连接。
- `d_ex()` 仅在函数体确认为查询 `obj_dialoguer` 是否存在时当作只读。`waitbox/halt` 同时核验队列处理器及 `scr_halt`；第四章 `k_d` 的 `scr_doom` 清理路径还核验唯一的对象事件。未证明的同名函数不放行。

局部 `con` 或 `customcon` 声明会遮蔽状态或等待字段，均停止连接；状态写入检查也包含取余、位运算、移位及其他复合赋值，不能只检查 `=` 和加减。对应反例会被拒绝。

公共后文放在分支外，沿用 `join_next`。若回答先有公共文字、再按答案分流，格式支持可选 `choice.prefix = {type: "sequence", children: [...]}`；网页依次展示选项、公共文字一次、按选项编号区分的回答。同文件队列当前没有获证的公共正文前缀；共享连续选择使用该字段保留下一题未使用选项槽的公共引用，不能把这些空白引用算作新接通的公共台词。

## 直接对话框与二次提问

`direct_local_choice` 处理 `msgset/msgnext`（含已核验的本地化版本）与 `d_make` 创建的同文件菜单。它与队列选择分别发现入口，复用响应、嵌套问题和引用保留结构；目前匹配第四章 2 处、第五章 6 处。

- 每题须在自己的路径上设置 `global.msc = -99`、清空 `global.choice`、写入固定选项及唯一提示；文字、选项 getter、对话框、writer、选择器及返回脚本均核验源码。
- 只连接唯一、向后的常量 `con` 响应，响应入口须为 `con == 常量 && global.choice != -1`。不放宽超时入口、多个来源共用目标、动态状态或局部遮蔽。
- `d_make` 可以在分支内，也可以位于 if/else 之后的简单公共语句段。无条件目标状态写入可以在祖先语句段中；路径上后续条件改写该状态时拒绝。直接对话框句柄只在当前语句列表中绑定，有限常量显示属性可保留，句柄改写后失效。
- 先独立证明下一题，再把它嵌入上一题对应的回答。回答中的 flag 判断保持原样；没有文本的取消项留空，后续动画状态不自动接入。未核验的调用或赋值仍阻止连接。
