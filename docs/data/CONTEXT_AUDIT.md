# 上下文开发审计

选择题和条件差分统一进入独立审计清单，供开发排查、确定批次和比较变化。清单只生成在本地 `build/`；不进入 `dist`，不向网站增加标签或提示。它不改变分析器现有连接，也不解释 flag 的剧情含义。

## 输入与输出

命令见[构建说明](../build/README.md)。输入是当前五章 GML、语言快照和已生成的完整上下文包。工具先核验语言、分包以及全部 GML 的摘要，再在内存中重新分析并与现有结构比较；输入或分析器结果过期时停止，不能将新源码的候选与旧网页结果混报。

| 文件 | 用途 |
|---|---|
| `registry.jsonl` | 每行一条登记记录，包含位置、作用域、原始表达式、文本样本、状态和原因 |
| `summary.json` | 按类型、状态、章节和原因计数，绑定上下文、语言、源码集合及审计工具摘要 |
| `sources.json` | 全部五章 GML 文件摘要，包括没有本地化文本的文件 |
| `review.md` | 可阅读汇总、阻断原因及每类代表位置 |
| `changes.json` | 首次为基线；指定 `--previous` 后列新增、移除、状态／原因变化和源码变更 |

输出不能覆盖原料、语言表、上下文包、网站目录或用于比较的旧审计目录。后续批次采用新的输出目录保留基线。记录从清单中消失不代表已经修复；源码版本变化时要重新核对。

## 登记范围

发现候选独立于成功连接，先从源码和第一章英文表寻找控制串，再与现有关系对账。

| `kind` | 内容与计数口径 |
|---|---|
| `choice` | 已知文本函数、消息缓冲区或其他字符串中的显式 `\C1/2/3/4`；共享脚本、直接消息、队列在同一清单中 |
| `condition` | `if/switch` 中含本地化引用、已知消息调用、答案读取，或被现有规则确认影响后文的提前退出检查 |
| `signal` | 选项存储写入、答案读取／转存、选择器创建和动态消息参数；这些不是额外的菜单数量 |
| `condition_gap` | 与文本或答案相关，但处于匿名函数等未解析作用域中的条件，或未展开的三元表达式 |
| `choice_call` | 已确认的跨文件选择回调调用位置，关联原始选项与来源提示；不与提示重复计题 |
| `projection_gap` | 现有 choice 节点尚未找到唯一源码提示的审计映射缺口；必须显式报告 |
| `file_gap` | 所扫描相关文件的解析失败 |

每个记录绑定章节、文件摘要、原始偏移和行号；位置 ID 只在相同导出格式下适合比较，不是跨版本语义 ID。同 key 的不同 occurrence 和各章副本不会合并。每个记录及分支范围提供首条本地化文本样本，`count/identity_sha256` 对应范围内全部本地化引用，样本不是完整文本列表。

记录保留父条件、函数、case、with 等作用域。`option_candidates` 是局部可读取的候选标签；只有与产物中完整选项 occurrence 集合对应、且不存在多个提示竞争时，才记为已连接。共享回调单列适用的调用位置，不能推广到所有调用者。

条件的 `contained_choice_ids` 指向源码范围内的选择提示；`text_contained_in_choice_ids` 指向其文本被纳入的选择回答。这两个字段表示包含关系，不把所有内部条件都解释为读取该次答案。

## 状态与解释

选择提示的状态：

- `linked`：与现有 choice 节点的选项 occurrence 精确对应。
- `linked_at_callsite`：通过已验证的回调在指定调用处连接，适用范围保留。
- `unconnected`：已登记提示，但当前没有相应连接；记录规则的首个阻断原因。
- `uncertain`：字符串是否真正用于菜单、或对应关系仍有歧义。

条件的状态：

- `represented`：原表达式与引用范围已经保留在上下文中。
- `represented_guard`：已保留为前置检查或块条件。
- `represented_in_choice`：相关答案文本已纳入选择结构。
- `represented_revisit`：已有局部 flag 写入证据支持首次／再次排列。
- `unresolved`：间接消息、switch 流转、缺本地文本或没有对应投影等情况。

条件另按表达式中可见的 `global.choice`、flag、Side B、其他 global 状态、流程变量及其他表达式分类；这是语法分类，不推测剧情。`text_shape` 区分两侧／多侧有文本、只有一侧有文本、没有本地化文本。`meaning=unreviewed` 和 `execution=unproven` 始终保留：源码条件被展示，不等于含义、可达性和执行顺序均已确认。

`reasons` 是登记状态的原因；`rule_diagnostics` 保留现有规则给出的结果。规则通常在首个检查失败时停止。`observations` 可另列独立语法事实，例如提示之后只有空白消息槽、下一 case 又含选择提示；这些线索不是修复安全性的证明。原因可并列，不能把原因数量相加当作菜单数量。

## 限制与验收

独立答案判断批次对照 `build/context-shared-chain/audit` 基线，当前结果在 `build/context-independent/audit/`。1,340 个选择提示的登记分母未变：已连接由 204 增至 247（含 1 个限定调用处连接），未连接 1,083，不确定 10；109 个条件由原式展示变为回答包含于选择结构。记录无新增、无移除、无来源重绑定，全部 247 个网页选择均有登记对应。另有 223 条原因或诊断变化，不计作修复数量。清单状态仍不进入网站。

清单分母是当前发现器能识别的源码位置，包含旧文本、测试文本和跨章副本，不是独立游戏场景数。没有这些信号的跨文件变量影响、任意动态拼接、自定义菜单及完整可达性求解不在当前分母内。`switch` 只登记 case 文本范围，不推断穿透或汇合。

回归覆盖第一章表内控制串、注释伪例、空格选项填充、动态消息、匿名函数、三元表达式、相同 key 的不同用法、跨章身份、多个提示竞争同一投影、共享回调和状态差分。每次重跑须检查所有现有选择节点均有登记去向，并核对新增或变更原因的代表源码；通过库存对账不能代替逐类语义验收。
